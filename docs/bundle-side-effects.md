# `sideEffects` — investigated, deliberately NOT declared

**Verdict (2026-08-23, v2.76.0): DO NOT declare `sideEffects` in `package.json`.**
Not `false`, and not the array form either. The bytes it buys are small; the
failure it risks is silent and uncatchable by any gate in this repo.

This note exists so the next person does not re-derive it. If you are about to
add the field because a bundle-size audit flagged its absence — read this first.

## Why it looks tempting

Without the field, a consumer's bundler must assume every module in the package
may have side effects and cannot elide unused ones. Declaring it is the last
remaining tree-shaking lever (the big win, externalising `cmdk`, already landed
in v2.73.0).

## What was actually measured

A scratch consumer outside the repo, **webpack 5.109.2**, `mode: production`,
the library installed from `npm pack` output (not a `file:` link, so the real
published shape). webpack is the right test bed — it honours `sideEffects` far
more aggressively than esbuild/rollup.

Two scenarios, each built and — for correctness — **executed**:

- **correctness**: import the renderer registry through the published entries
  and assert `getFieldTypes()` / `listRegisteredRenderers()` / `getRenderer()`
  actually resolve.
- **size**: import only `Chip`, measure emitted bytes.

| `sideEffects` value | root `getFieldTypes()` | `/doc-editor` | `styles.css` | `Chip` from `/shared` |
|---|---|---|---|---|
| *(absent — today)* | **7** field types, 22 renderers | 7 / 22 | emitted, 164,486 B | 31,095 B (gzip 9,375) |
| `false` | **0** — everything null | 7 / 22 | **DELETED** | 30,142 B (gzip 9,134) |
| `["**/*.css"]` + renderers glob | **0** | 7 / 22 | emitted | 30,142 B |
| `["**/*.css","**/index.js","**/index.cjs"]` | **0** | 7 / 22 | emitted | 30,142 B |
| `["**/*.css","**/renderers-*.js","**/renderers-*.cjs","**/index.js","**/index.cjs"]` | 7 / 22 | 7 / 22 | emitted | 30,142 B |

Every one of those builds reported **`compiled successfully`**. The broken rows
produce no error, no warning — just an empty registry at runtime.

Two independent breakages under `sideEffects: false`:

1. **`import '@connorhoehnslalom/ui-components/styles.css'` is deleted outright** —
   the whole 164KB stylesheet vanishes. (Fixable with `"**/*.css"`.)
2. **Renderer registration is silently erased.** `getFieldTypes()` → `[]`,
   `getRenderer('rich-text','reader')` → `null`, and even the `('*','*')`
   wildcard fallback → `null`.

## Why the array form does not rescue it

`src/renderers/index.ts` is the only module-level side effect the library ships
(verified by scanning all of `src/` for top-level call expressions —
`test-setup.ts` is not published, and the one `identity` hit is text inside a
JSX template literal). Its 7 `registerFieldType` + 22 `registerRenderer` calls
run at import time.

In `dist`, those calls land in a **content-hashed chunk**, `renderers-<hash>.js`.
The root entry reaches them only like this:

```js
// dist/index.js
import { o as vr } from "./renderers-Cdzaaplv.js";
```

`vr` is not the registry. It is **a modal component** that rollup happened to
place in the same chunk, referenced once in some unrelated root-exported
component. The registrations survive today purely because that incidental edge
keeps the chunk alive.

The array form is a **whitelist**: every file you do not list is asserted pure.
So making it safe means naming the chunk that carries the registrations — and
the measurements above show that even that is not enough on its own. Only the
*conjunction* of `**/renderers-*.js` **and** `**/index.js` works. Drop either
glob and the registry silently empties.

That conjunction is not a contract:

- `vite.config.ts` sets no `manualChunks` and no `chunkFileNames`. The
  `renderers-*` name is an emergent rollup artifact of the current import
  graph, regenerated by every build.
- If a refactor moves that modal out of the chunk, splits the renderers barrel,
  or lets rollup inline the chunk elsewhere, the glob stops protecting anything.
- `**/index.js` being side-effectful also forfeits most of the root-entry
  tree-shaking the declaration was supposed to buy.

## Why the payoff does not justify it

For the import path that actually matters — a subpath import, the one a
size-conscious consumer uses — the safe declaration saves **953 bytes raw /
241 bytes gzip** on a `Chip` import (31,095 → 30,142; gzip 9,375 → 9,134).
About 2.6% gzip.

Root-entry imports do improve more (total emitted 2,065,345 → 1,425,157 bytes),
but a root `Chip` import still ships a 627KB initial chunk. Anyone who cares
about size must use subpaths regardless, where the win is ~240 gzip bytes.

## Nothing in this repo can catch a regression

This is the decisive argument. If the chunk graph shifts and the globs stop
matching, **every gate stays green**:

- `npm test` — vitest, no bundler, `sideEffects` never consulted
- `npm run build` — rollup, different tree-shaking model
- `src/__tests__/packaging.test.ts` — checks externals/types/export targets
- `npm run test:e2e` — Playwright against the **vite** demo

The break would surface only in a downstream webpack app, as a document-type
picker that renders empty. Correctness beats 241 gzip bytes.

## The unblock, if someone wants this later

The blocker is structural, not a `package.json` problem: the registry is
populated by a module-level side effect reachable only through an incidental
chunk edge. Remove the side effect and the whole question dissolves —

Make registration **lazy and idempotent inside `src/renderers/registry.ts`**:
have `getFieldTypes()` / `getRenderer()` / `getFieldType()` ensure the built-in
definitions are installed on first read, instead of relying on
`src/renderers/index.ts` having been evaluated. Then the library has no
module-level side effects at all, and

```json
"sideEffects": ["**/*.css"]
```

becomes both safe and sufficient — no chunk-name globs, no conjunction, no
cliff.

That touches `src/renderers/` and `src/index.ts`, which is on the no-touch list,
so it needs a handoff. Pair it with a consumer-side regression test (a real
webpack build asserting a non-empty registry) before declaring anything.
